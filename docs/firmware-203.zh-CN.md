## Root shell 与备份

该相机的旧终端路径失败，FileControl 返回 `0x80` 且无数据。Jiritsu 加载器可以启动持久 root shell，后续命令保留 PID、变量及工作目录。这里的“持久”指一次会话内保留状态，不是重启后自动 root；不能仅凭 Jiritsu 名称就断言它是官方维修接口。

root 使用 `dd` 将块设备按 512 KiB 分块读入 tmpfs，再通过 Jiritsu 下载，每块比较相机与主机 SHA-256。实测速率约 **1.3 MiB/s**，用户区单遍约 25 分钟。按机主要求，在 **1,681,915,904 字节**处停止；**该早期实验没有读完全部区域；随后完整单遍已成功，见页首。独立双遍仍未验证**。同一相机升级前在 2.02 下已通过 fastboot 完成全量双备份。慢速备份及取消方式见 toolkit 的 Jiritsu 文档。

实测可在内存 shell 仍运行时，先删除并核对闪存加载器/脚本/输出，再关闭服务并断电。提前终止 shell 会反复导致后续 USB 读取超时，内部原因未确定。本次整理的取消及清理实现只做了离线验证。

完整 `CautionConfig.so` 为 17,694,160 字节，与已知 2.02 原版相同：

- 原版 SHA-256：`5ad8746a229da259fe00b297e8f897d682f7ae9a13393025b3d1c95a808e68d7`。
- 修改后 SHA-256：`14f42cc09ee1b9ddde5352482c13b68e5a5e97d9d79e8456087b5e0b7af6ff6a`。
- 全文件只差一字节：偏移 `0xD778E4`，`20 → 1B`。
- 三个 Backup 属性：`0x01071C54=01`、`0x00A5000B=02`、`0x00A5000C=16`；机主确认中国大陆 B=2/C=22。

文件与属性已经保留，但暖恢复仍加载旧四项页面。因此执行独立的 WBI 流程，先保存两份相同的完整 60 MiB 原始镜像，并在写入前再完整读取一致：

- 原始 SHA-256：`aa584ec93b17f786e6ffbdfe732ce351a17d3219119f0c549741999eea4832e5`。
- Sony 输出：`[UD_WBI_DROP] /dev/nflasha5 wbi_drop`。
- 执行后 SHA-256：`2e78fd8a55186d1b28c688a96fee2a812d357bc40520408fc8cffea9389787e2`。
- 完整逐字节比较：只有首 512 字节清零，其余全部一致。

`/usr` 已恢复只读，上传的辅助文件已清理。断电重启后，**机主确认原生频段选择菜单出现**。尚未采集该次重启后的 TypeNB/活动无线状态，也未验收 2.03 的实际 5 GHz 热点传图及路由器操作，不能把 2.02 的功能结果算到 2.03 上。WBI 首扇区失效是“一字节加三个属性”之外的额外磁盘变化，正常日志/缓存也可能变化。
